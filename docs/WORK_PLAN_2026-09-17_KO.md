# 현재 작업 순서와 모듈화 체크포인트

## 이번 범위: 보존하고, 작은 책임부터 분리한다

출력·오류 복구 검증만으로 실제 파트너 기능이 완성되지는 않는다. 목표 기능,
현재 코드, 통합 여부, 실게임 증거를 구분한다. 먼저 기존 작업을 원격에 보존하고
검사 가능한 작은 구조 변경을 별도 커밋으로 남긴다.

- `ca9bc79`: 외부 provider 워커 시간 제한·정리, mock임을 명시하는 응답.
- `a80eb2c`: alpha.6~9 UI·초상화·복구·진입점 구현과 검증 한계 기록.
- 두 커밋을 개발 브랜치에 push했고 GitHub CI 성공을 확인했다.
- 게임 파일, bridge 기록, API 키, 로컬 dist/백업은 올리지 않았다.
- 이후 모듈 추출은 별도 commit/push. main 병합이나 공개 release는 아니다.

## 구조 변경

| 모듈 | 소유하는 책임 | 하지 않는 일 |
|---|---|---|
| `scene_adapter.py` | 활성 심·가족 조회, 스냅샷, 바인딩된 실제 심 찾기 | UI, 파일, API, 역할 자동 선택 |
| `conversation_state.py` | 현재 요청·표시·대기 종료·시간 만료 판정 | 장기 기억, 저장 계보, 원격 취소 |
| 기존 `role_binding.py` | 역할·씬 식별과 유효성 | 통신·대사 |
| 기존 UI 모듈들 | 메뉴·선택·입력·표시 | 모델 호출·기억 DB |
| `commands.py` | 등록·의존성 연결·기존 실행 경로 | 새 관찰/욕구 로직을 직접 누적하지 않음 |

`commands.py`는 748→687줄. 총 줄 수를 줄이는 것이 목적은 아니다. 새 모듈은
게임 SDK 없이 검사할 수 있고, 대화 상태 다섯 전역변수를 한 객체로 관리한다.
scene 함수도 EA 객체를 접근하므로 여전히 게임 스레드에서만 호출한다.
기존 명령 및 얇은 wrapper는 호환성과 점진적 이동을 위해 남겼다.

전체 모듈화가 끝난 것은 아니다. bootstrap 설정/수명과 대화 UI 연결 로직은
아직 commands에 있다. 기능 연결에 필요한 경계에 맞춰 다음 추출을 진행하며,
줄 수만 줄이기 위해 빈 계층이나 전달만 하는 클래스를 늘리지 않는다.

## 다음 작업과 종료 조건

1. **첫 구조 정리 저장** — 검사·빌드 후 commit/push, 원격 SHA와 작업 트리 확인.
2. **콘솔 없는 대화 한 사이클** — launcher 반복 사용부터 mock 답변까지 실게임
   확인. 마치면 문구 다듬기만 반복하지 말고 기억 통합으로 넘어간다.
3. **클로드 기억 코드 통합** — `claude/memory-slice`의 `bbdee0d`를 검토해 재사용.
   commands의 욕구 읽기는 scene 경계로 옮긴다. memory.py의 저장/검색/정리 분리는
   통합과 한 덩어리로 몰지 말고 검사 가능한 순서로 진행한다.
4. **동일 세션 대화 연속성** — 앞서 말한 내용을 다음 턴에 쓰되 다른 역할·세션은
   섞지 않는다. 현재 `turn-<request_id>`는 매 턴 달라 그대로는 회상할 수 없다.
   기록 고지/선택, 입력·검색 예산, 발화와 관찰 사실의 출처 구분부터 확인한다.
5. **관찰 하나 → 기억 후보 → 대화 반영** — 배우/대상 방향과 중복/취소 검증.
6. **승인받은 안전 행동 하나** — 실행/완료/취소를 관찰한 뒤 자율행동 확장.

유료 API 시험은 최종 검사 때 별도 승인 예산으로만 진행한다. 한 단계의 성공은
전체 RFC 구현 완료나 공개 배포 승인을 의미하지 않는다.

## 같은 날 두 번째 모듈화: 답변 표시와 메뉴 내용

- `reply_presenter.py`로 답변 검증 후 표시, 파트너 초상화, 콘솔 fallback,
  실패/시간초과 시스템 안내와 표시 완료 처리를 옮겼다.
- 만료·역할·장소·중복 검사는 commands 쪽의 기존 진입 경로에 유지했다.
  presenter는 사실 기억이나 행동 실행 권한을 갖지 않는다.
- 메뉴 문장·역할 미설정 안내·로컬 접수 표시 구성은 `ControlUI.open_home`으로 이동.
- 기존 384개 회귀 검사 그대로 통과 후 새 모듈 단독 검사 11개를 추가해
  **395개 통과**(15.857초). 계약 export 및 diff 검사도 통과.
- 게임 Python 3.7 빌드: 13개 root pyc. 후보 파일은
  `dist/PlumbMate-alpha9-presentation-refactor.ts4script`.
- SHA-256: `992e592663ccd1ee2683503fe629896b4dd3d1ab6c65ec0d412223206ff58aee`.
- commands는 687→668줄. 전체 줄 수 감소보다 표시 책임을 독립 검사할 수 있는
  경계를 만드는 작업이다. 대화창 라우팅과 bridge lifecycle 전체 이전은 하지 않았다.
- 이번 변경도 설치/실게임 검증을 하지 않았고, 새 제품 기능을 추가한 것이 아니다.

## 9월 18일: 통신 수명 분리 — 작업별 성과 기록

사용자 요청에 따라 누적 테스트 총수를 이번 작업 성과로 표시하지 않는다.
직전 작업은 표시/메뉴 책임 분리 + 신규 11개 검사였으며, 그 커밋
`d5b4f47`의 원격 CI 두 실행도 성공한 것을 확인했다.

| 이번 작업 항목 | 결과 |
|---|---|
| 완료한 구조 작업 | 통신 시작/정지/재바인딩 수명을 `BridgeLifecycle` 한 객체로 분리 |
| 전역 상태 정리 | bootstrap client, endpoint, autostart 상태 3개를 객체 내부로 이동 |
| 명령어 파일 | 668 → 620줄; 파일 읽기 어댑터와 안내/등록은 유지 |
| 새로 추가한 검사 | **15개**: 독립 수명 검사 14개 + 모듈 누락 시 진단 유지 1개 |
| 기존 회귀 검사 | 기존 **395개 통과**; 새 검사 추가 전에도 별도 실행해 확인 |

| 계약/빌드 | 계약 export, diff 공백 검사, 게임 Python 3.7 빌드 통과 |
| 실게임/설치/API | 이번에는 하지 않음; 설치본 변경 및 유료 호출 없음 |

새 검사는 비활성 설정, 토큰 누락/손상, 런타임 사용 불가, tick 중 설정 재조회
금지, 미접속 bootstrap 교체, 재시작 실패 시 기존 연결 유지, 중복 stop,
훅 제거 실패, close 예외, 초기 훅 실패, 명시적 재시작, attach 실패를 다룬다.
동일 client는 한 번만 닫고, 다른 client의 close가 실패해도 나머지는 정리한다.
훅 제거가 실패해도 binder를 비우고 driver를 정지해 자동 부활을 막는다.

빌드 후보: `dist/PlumbMate-alpha9-lifecycle-refactor.ts4script` (14개 root pyc).
SHA-256: `f83cc514c07061aeeea2cd9f7db93a3723b045183c53d68786a448532b4325c9`.
이번 분리도 구조 검사/로컬 예외 검증이며 실게임 동작 입증으로 세지 않는다.

다음 우선순위는 alpha.9 후보의 **콘솔 없는 메뉴 → 역할 → 한글 입력 → 답변
알림** 한 사이클 실게임 확인이다. 이 문턱을 통과하면 문구 테스트 반복 대신
기록 고지/선택과 세션 경계를 포함한 대화 연속성 통합으로 넘어간다. 대화 UI
라우팅은 아직 commands에 남아 있으며, 새 기능과 함께 무리하게 추출하지 않는다.

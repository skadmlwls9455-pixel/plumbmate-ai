## Autosave slot — static path confirmed

`AUTO_SAVE_SLOT_ID = 4294967295` (`0xffffffff`) was confirmed in the module body of `services/persistence_service.pyc`. member SHA-256: `96d4ffd7c4696232306d7aff7ae977c5d9eeaa5599425b71a4df984dcecc58d1`.

`PersistenceService.save_game_gen` calls the manual-save-complete callback when the result is success, `slot_id > 1`, and `slot_id != AUTO_SAVE_SLOT_ID`. This check itself is also inside the `send_save_message` branch, so that single manual callback must not be used as the completion signal for all saves.

The current build's `AutosaveService` actually exists, reads real-time/game-time/build-mode-exit settings, and forwards the `REQUEST_AUTOSAVE` op to the client. This is the basis for distinguishing that slot as the current build's engine autosave reserved slot. However, it is not a basis for classifying autosaves by other mods that use ordinary slots as manual, and the shared reserved slot ID is not a save lineage identity either. An actual autosave was not executed for testing.

## 2026-09-05 static confirmation of the zone tick injection point

`zone.pyc` was marshal-loaded with the game's `libpython370.dylib` and its code object was read directly. No game modules were imported and the game was not run.

- `Zone.update` exists, with `co_argcount=2` and `co_varnames[:2] == ('self', 'absolute_ticks')`.
- The same class also has `_gather_tick_metrics(self, absolute_ticks)`, `tick_data(self)`, `start_gathering_tick_metrics`, and `stop_gathering_tick_metrics`. These names are circumstantial indications that `update` is a per-frame tick path, not evidence of call frequency.
- `Zone` also has `register_callback`/`unregister_callback`, but within the checked scope they are zone lifecycle callbacks, not tick callbacks. That is why an `update` wrapper was used instead of a registration API.
- member SHA-256: `735c3463d9f8bcaf88f5d2f530c03556cf79a741a07bba72430ddb416ccf5658`
- Python used for the check: `3.7.0` (game's built-in runtime)

`plumbmate_tick_driver.install_tick_hook` calls the original first and then calls `driver.on_tick(absolute_ticks)`. If the original throws an exception, the pump does not run.

This is only static evidence of the signature's existence. The actual call frequency, the budget of one tick, the ordering when another mod wraps the same method, and whether the wrapper remains on game exit are **NOT_TESTED**.

(Follow-up: in the "In-game → companion app event round trip" item below, it was measured that the wrapper actually runs the pump. Call frequency and tick budget remain **NOT_TESTED**.)

The loopback round trip is `ROUND_TRIP_OK`. The stages are `listener_created → bound → listening → connect_ex_36 → accepted → connected → sent → received`, kernel-assigned port 61279, 136 spins. The 36 returned by `connect_ex` is macOS `EINPROGRESS`, exactly the non-blocking path used by the game-side client. Because `getpeername`/`SO_ERROR` were used for the round-trip judgment, the client's connection-completion detection path itself was verified.

It was confirmed that the `_socket` import failure in the earlier isolated diagnostic was an `@executable_path` problem. Inside the game process it loads normally.

### Correction: `select` exists

The earlier edition of this document (and a comment in `bridge_client.py`) scanned only `lib/` in `base.zip` and wrote "no select." C extensions are not in `lib/` but in `Contents/Frameworks/lib-dynload/`, and `select.dylib` actually exists. The select-free implementation is kept, but its rationale is not "because the module doesn't exist" but "because it handles only one socket, so no additional module is needed."

`ssl` and `sqlite3` are still unavailable, but the bridge does not require them. The bridge authenticates with nonce-based HMAC over plaintext loopback and does not use TLS.

This result applies to this build (`1.127.41.1230`) and this installation environment. The extension module composition may differ in the next patch, so the import guard in `commands.py` and the reason reporting in `plumbmate.status` are kept.

## 2026-09-05 in-game → companion app event round trip — live_tested, DELIVERED

With `PlumbMate.ts4script` placed into the actual game and the companion app `plumbmate listen` running, the in-game cheat console was used to run
`plumbmate.bridge.start` → `plumbmate.bridge.ping`. The received line was printed verbatim in the companion app terminal.

```json
{"kind": "heartbeat", "event_id": "c1596ec3f5e2472897f2405aa161d80a", "payload": {"source": "cheat_console"}, "received_at": "2026-09-05T06:04:38.215999+00:00"}
```

This one line matches the format in which the `listen` loop of `cli.py` prints events received from `server.poll()`. That is, a socket created directly by the game process
attached over loopback, completed the handshake, and sent an event frame. For this path to hold, all of the following
must actually work, so each becomes **live_tested** through this observation.

| Stage | Evidence |
|---|---|
| Socket creation and non-blocking connect inside the game | If the server could not accept the connection, the stages below would not exist |
| Nonce-based HMAC authentication | `EventSocketServer` sends `welcome` only if the `hello` proof is correct, and the client does not send events before `welcome` |
| newline-delimited JSON framing | The server parsed the frame and restored `kind`/`event_id`/`payload` |
| The `Zone.update` tick hook actually runs the pump | `plumbmate.bridge.ping` only does `queue_event` and does not touch the socket. Sending happens only in `pump()`, and `pump()` is called only by the tick hook's `TickDriver.on_tick`. Since the event arrived, `Zone.update` was called at least once after the hook was installed |
| Permitted send kind list | `heartbeat` passed the allow lists on both sides |

The tick injection item in the earlier document was only static evidence of the signature's existence. With this observation, it was measured up to "`Zone.update` is called and its
wrapper runs the pump."

Still **NOT_TESTED**:

- Tick call **frequency** and the budget of one tick. The arrival of one event is evidence that "it was called at least once," not evidence of a cycle.
- Receipt of ack on the game side. This observation is only one line in the companion app terminal, and `acked_events` of the in-game `plumbmate.bridge.status` was not
  recorded alongside it. Whether the server sent an ack is not established by this line.
- Long-duration connection maintenance, reconnection after companion app restart, behavior during save, lot transition, and Sim reset.
- Ordering when another mod also wraps `Zone.update`.

Because `Zone.update` runs only in a loaded zone, this observation can be considered to have come from a state with a zone loaded, not the main menu.
However, which household/lot it was was not recorded. The event payload is only `{"source": "cheat_console"}`, and
no save was created and no external address was contacted.

## Confirmed facts

| Area | Confirmation result | Design conclusion |
|---|---|---|
| Sim instance | `SimInfo.get_sim_instance(...)` returns `None` if there is no live reference, and `SimInfo.is_instanced(...)` judges by that result. | Action feasibility is checked separately via the actual instance, zone, and queue, not whether the household is active. |
| Queue ownership | The game action queue is on the instanced `Sim`, not on `SimInfo`. During `Sim.__init__` there is also an initial period with `queue=None`. | Do not inject immediately on `is_instanced=True` alone; also confirm startup completion and queue availability. |
| Rabbit hole end registration | `RabbitHoleService.set_rabbit_hole_expiration_callback(sim_id, rabbit_hole_id, callback)` registers a callback in that rabbit hole's `end_callbacks`. | Top candidate for detecting rabbit hole return in the current build. Must be registered after obtaining the rabbit hole ID. |
| Rabbit hole end call | `RabbitHole.on_remove(canceled=...)` calls `end_callbacks(canceled=...)`. | Distinguish normal end from cancellation to resume or replan the IC. |
| Career end internal path | `CareerBase._end_work_callback` exists and performs the `leave_work()` or `end_career_session()` path. | It is a private internal method. Prefer the rabbit hole service callback and observable state changes over direct patching. |
| Sim reset | `Sim.on_reset_internal_state(...)` calls `self.queue.on_reset(...)` and emits `TestEvent.OnSimReset`. | On reset, invalidate PlumbMate-owned actions and find the new Sim/queue again. |
| Queue reset | `InteractionQueue.on_reset(...)` cleans up the transition controller, running interaction, and buckets. | There is no evidence that this path makes the queue object itself `None`. Do not recreate the queue object directly. |
| Interaction source enum | `interactions.context.InteractionSource` exists and includes `PIE_MENU`, `AUTONOMY`, `SCRIPT`, `SCRIPT_WITH_USER_INTENT`, etc. | The symbol names are confirmed, but `SCRIPT` is not a PlumbMate-exclusive value, so it is not sufficient as an action ownership marker. |
| Interaction complete channel | `Interaction._trigger_interaction_complete_test_event` calls `services.get_event_manager().process_event(TestEvent.InteractionComplete, ...)` per participating Sim. | Use the common event receiver. Merge multiple participant notifications of the same execution into one event. |
| Buff and mood channel | `BuffComponent.add_buff`, `remove_buff`, and `_send_mood_changed_event` also have the same `get_event_manager().process_event(...)` path. | `BuffBeganEvent`, `BuffEndedEvent`, and `MoodChange` can be registered with the common manager. Whether notifications occur on all load/remove paths is tested further. |
| Need value channel | `BaseStatisticTracker.add_watcher(callback)`/`notify_watchers(stat_type, old_value, new_value)` directly call tracker-internal callbacks. | Do not assume that subscribing to EventManager alone receives all needs. |
| Natural decay and thresholds | `ContinuousStatistic._update_value` updates the value by elapsed game time and calls `notify_delta`. Separately, `_update_active_callback` schedules threshold alarms. | Distinguish the scopes of general watchers, delta watchers, and threshold listeners, and test natural decay. Because `_update_value` updates `_value` after the delta notification, check in the next processing interval rather than re-reading immediately in the callback. |

## 2026-09-05 static confirmation of event channels

Registration with the common manager is `EventManagerService.register(handler, event_types)`, and the receiving convention is `handler.handle_event(sim_info, event_type, resolver)`. It was confirmed that the `_process_test_event` bytecode calls this method directly. The registration path can be verified first without needing to patch emitter methods with private names. This is not a claim that it is a public modding API whose stability EA guarantees.

Needs are registered separately with the tracker. `create_and_add_listener` can add statistics depending on conditions, so a read-only observer must select only already-existing statistics and check for registration side effects. The callback arguments of general `notify_watchers` are `(stat_type, old_value, new_value)`. Initial baseline values and threshold behavior are verified in-game.

## Limits of dynamic markers and isolated imports

It was confirmed that `Interaction.__init__` does `copy.copy` of the context and that `InteractionContext._clone` also does a shallow copy. This is evidence of context copying, not evidence that `_plumbmate_decision_id` attached to an interaction object propagates to or disappears from child interactions. Marker persistence keeps the per-stage `NOT_TESTED` status of the [experiment specification](../RUNTIME_REVIEW_2026-09-05.md).

The isolated libpython diagnostic confirmed Python 3.7.0 and the `.dylib` extension module format. `ssl.pyc` exists, but `_ssl` and `sqlite3` imports failed. `_socket.dylib` does exist in the game's Frameworks, but from the diagnostic executable's location the `@executable_path`-dependent path differed and the import failed. Therefore this experiment must not be used to conclude that "socket is not available in the game either." The actual in-game import check is separate, and the product boundary of not using HTTPS/SQLite inside the game is kept.

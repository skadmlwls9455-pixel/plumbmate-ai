# alpha.8 사용감·실패 복구 체크포인트

유료 테스트는 사용자의 요청에 따라 최종 검사까지 보류. 결제, 키 설정,
실제 모델 호출, 예산 상향, 공개 배포를 하지 않았다.

## 구현

- `plumbmate.chat` 재개 시 이미 보낸 요청이 있으면 새 입력창 대신 상태창.
  처리 확인 없음/처리 중, 경과한 실제 시간, 자동 수신 여부를 구분한다.
  예상 완료 시각이나 캐릭터 감정은 지어내지 않는다.
- 상태창의 **닫고 기다리기**/Escape는 대기를 취소하지 않는다.
  **기다리기 끝내기**만 해당 요청의 이후 알림과 수동 읽기를 막는다.
  콘솔 대안은 `plumbmate.dismiss`.
- 종료 직전에 요청·역할·장소를 다시 검증한다. 이미 도착했거나
  다른 요청을 보낸 뒤 오래된 상태창을 눌러도 새 대화를 건드리지 않는다.
- 전송된 요청/과금 취소와 화면 대기 종료를 분리해 안내한다.
  재전송·기록 삭제·과금 예약 해제는 하지 않는다.
- 자동 알림이 누락됐어도 대화창을 다시 열면 정확히 그 요청의 준비된 답변을
  읽는다. 손상된 상태/응답 기록도 대기 종료 UI를 열 수 있다.
- 역할이 없으면 빈 채팅 대신 역할 설정으로 연결. 한 심 가족의 한계는
  콘솔뿐 아니라 시스템 알림으로 안내하고 심을 자동 생성하지 않는다.
- 과금 차단은 다시 보내기/재시작으로 해제되지 않는다는 안내 강화.
- 외부 HTTP만 별도 spawn 프로세스에서 실행. 고정 1 MiB 공유 결과 버퍼;
  입력 토큰 확인 30초/생성 60초 제한, 종료 정리에 최대 2초씩 추가.
  부모 동반 앱이 과금 원장을 소유하며 미확정 금액을 계속 보류한다.
  게임 스레드에는 파일 폴링·프로세스·스레드·API 호출을 추가하지 않았다.

## 검증 근거

- 무료 자동 검사 356개 통과. 이전 341개 대비 신규 15개.
  전체를 두 번 실행해 15.540초/15.412초에 각각 통과했다.
- 실제 spawn 자식 프로세스를 고의 지연시켜 시간 초과 → 자식 정리 →
  다음 로컬 모의 요청 성공 확인. 네트워크/유료 모델은 사용하지 않았다.
- 중복/오래된 창, 역할·장소 변경, 대기 종료 후 새 전송, 준비된 응답 회수,
  손상된 기록, UI 실패 후 중복 실행 차단을 검사했다.
- 설치 게임의 `ui/ui_dialog.pyc`에서 `UiDialogOkCancel`, `ButtonType` 및
  OK/CANCEL 응답 경로를 오프라인으로 확인했다. SHA-256:
  `c0c98ecebbb9f0240f25ab7ed2efed07cb0b6f75be2e41d69fe44f8ba2280849`.
  새 상태창은 `accepted` 추정 대신 정확한 OK 응답 식별자를 확인한다.
- 게임 Python 3.7로 9개 production 모듈 빌드/magic 검사 성공.
  게임 프로세스가 없는 상태에서 실제 Mods의 PlumbMate 한 파일만 교체했다.
  새 설치본 SHA-256: `44999c9243425a261788467bfc20af1bf5e215187476384dd63755a557f2f465`.
  기존 alpha.7은 `dist/install-backups/2026-09-12-alpha8/PlumbMate.ts4script`에
  백업했고 SHA-256 `058551e8f2dd0c95d7205c54096e740a3e4b46f2bb72444273ceec9591300b4d`를 대조했다.
- 이것은 실제 화면/Windows/실제 API 검증을 대체하지 않는다.
  설치본 alpha.7의 초상화 성공을 새 상태창 검증으로 재사용하지 않는다.

## 아직 남은 사항 — 완료로 취급하지 말 것

1. 장문/이모지/Windows/다른 게임 빌드로 검증 확대. alpha.8 대기 종료 후
   새 한글 입력 → 새 mock 응답까지의 Mac 실게임 검사는 아래 기록처럼 완료.
2. 콘솔 없는 게임 메뉴 진입점. 현재는 `plumbmate.chat` 입구가 여전히 필요하다.
3. 기다리기 종료는 **화면 정책**이다. 서버에 아직 쌓인 요청을 취소하는
   계약은 미구현이고, 이미 보낸 원격 호출의 취소/환불도 보장하지 않는다.
4. 비용 차단 이유별 복구 GUI. 지금은 안내 + 동반 앱 `budget status`/
   명시적 정산 도구만 있다. 미확정 비용을 자동 해제하면 안 된다.
5. 실제 모델 자연스러움·인격 설정·장기 기억은 별도 구현/평가 단계.
6. 운영체제의 비정상적인 프로세스 생성/강제 종료 실패까지 실시간 상한을
   보장하지는 않는다. 종료 실패 시 다음 워커를 시작하지 않는 방어가 있다.

## 무료 실게임 검사 시나리오 (9/13 기본 경로 완료)

- 동반 앱을 켜지 않고 전송 → 대화 다시 열기 → 상태 확인 → 닫기 →
  다시 열어 대기 종료 → 이전 알림 차단 → 새 대화 전송.
- mock 동반 앱으로 정상 응답 확인 및 초상화/역할/중복 회귀 검사.
- 실험용 별도 bridge와 QA 저장을 사용하고, 기존 개인 기록을 지우지 않는다.
  실제 API 호출이 켜진 앱을 장애 실험 대상으로 쓰지 않는다.

## 2026-09-12~13 실제 화면 확인

- 실행 중 `plumbmate.status`에서 alpha.8 확인. BFF QA 가족이며
  플레이어 썸머/AI 트래비스 역할 선택. bare chat이 설정창을 먼저 열었다.
- 9/12 한글 입력 `대기창 확인용 메시지예요.` 전송 후 채팅을 다시 열어
  상태창 제목/경과 초/미연결 안내/두 버튼이 잘리지 않고 표시됨을 확인했다.
- **닫고 기다리기** 후 재개했을 때 같은 요청의 대기가 유지됐다.
- **기다리기 끝내기** 후 시스템 안내가 나오고 `plumbmate.read`가
  `기다리기를 끝낸 답변은 표시하지 않아요`로 차단됐다.
- 9/13 재개 시 역할이 초기화된 상태여서 다시 지정하고 새 mock 대기 요청
  `cb9d66f9832b413abbc1a00bc0ffbb7c`를 만들어 대기 종료를 다시 검사했다.
- 실제 companion은 `--provider mock --max-turns 8`로 재실행.
  이전 요청 `b4d3edefa4be47dcb740fc35214cf18c`와 위 요청이 완료됐지만
  대기 종료한 옛 답변은 게임 알림으로 다시 나타나지 않았다.
- Escape 입력은 먼저 콘솔을 닫았고 다음 입력도 상태창을 닫지 않았다.
  따라서 **Escape로 상태창을 닫는 UX가 검증됐다고 말하지 않는다.**
  화면의 `닫고 기다리기` 버튼은 정상이다.
- CUA 입력 초점이 콘솔 밖으로 빠진 동안 게임 단축키가 작동해 이동 지도가
  열리고 시간이 잠시 진행됐다. 이동은 취소하고 게임을 일시정지했다.
  수동 저장은 실행하지 않았다. 화면 검증 전체가 계속 일시정지였다고
  주장하지 않으며, 이 현상은 콘솔 없는 진입점이 필요한 추가 근거다.
- 콘솔 재개 단축키 자동화가 막혀 사용자에게 콘솔 개방만 요청했다.
  아래 재개 검사에서 남은 새 메시지 왕복도 완료했다.

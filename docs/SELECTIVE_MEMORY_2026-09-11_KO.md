# 행동 결과는 검증하고, 기억은 장면 단위로 선별한다

상태: 구현 전 정책 결정안. 현재 게임 관찰 수집기/영구 기억/요약 모델 호출에
연결하지 않았다. 기존 대화 파일을 삭제하거나 새 장기 기억으로 변환하지 않는다.

## 서로 다른 세 가지 질문

1. **실행 성공인가?** 행동의 완료/취소/실패 신호를 확인한다. 말했거나 큐에 넣은
   것만으로 실행 완료로 판단하지 않는다. 이 검사는 장기 보관과 별개다.
2. **기억할 가치가 있는가?** 로컬 규칙으로 사건 후보를 선별한다. AI 호출 없음.
3. **어떤 의미로 기억하는가?** 자격이 있는 근거 안에서 메인 모델이 짧은 해석을
   제안한다. 해석이 원본 사실을 덮어쓰거나 새 사실을 만들지는 않는다.

완료 신호도 해당 행동 어댑터의 의미를 검증해야 한다. 상호작용 종료 하나가
상대의 수락, 음식 전달, 관계 회복을 전부 증명하지는 않는다.

## 기본 기록 범위 제안

| 정보 | 어디에 얼마나 | 장기 승격 |
|---|---|---|
| 시작/완료/취소/경로 실패 | 짧은 크기 제한 진단 버퍼 | 원칙적으로 하지 않음 |
| 최근 함께한 활동·욕구 변화 | 세션 내 최근 사건 버퍼 | 후보 선별에 필요한 구간만 |
| 관계 변화·첫 경험·중요한 사건 | 근거를 가진 장면 후보 | 결과와 맥락 검증 후 |
| 약속·미해결 질문 | 별도 미결 항목 | 이행/취소/만료를 연결; 매번 복제하지 않음 |
| 반복되는 평범한 생활 | 횟수·기간·대표 근거 요약 | 반복을 확인할 때만 습관 후보 |
| 플레이어가 남기고 싶은 순간 | 플레이어 지정 항목 | 우선 보관하되 관찰/주장 구분은 유지 |

초기 실험 한도 제안: AI 심당 최근 사건 **128개 또는 게임 시간 4시간 중 먼저
도달한 한도**, 장면 후보는 **16개**. 실제 중요도와 장면 길이 평가 후 조정한다.
불러오기/분기/세션 변경은 시간 비교보다 먼저 범위를 격리한다. 역행한 게임 시간을
같은 시간축으로 이어 붙이지 않는다. 안정적인 저장 계보 전에는 세션 한정만 허용한다.
과부하로 버린 구간은 관찰 공백으로 표시하고 일어나지 않은 것으로 간주하지 않는다.

진단 원본 전체를 무기한 남긴다는 뜻이 아니다. 장기 사건에는 최소한의 구조화된
근거 묶음을 함께 남겨 추적 가능하게 하고, 나머지는 명시된 보관 정책에 따라 만료한다.
기존 로컬 채팅 아카이브는 아직 보관 UI가 없으며 이 정책만으로 자동 삭제하지 않는다.

## 후보 자격과 최종 선택은 별개

후보가 될 수 있는 경우:

- 확인된 중요한 세계 사건(화재·출생·사망·결혼 등). 패치별 실제 이벤트 의미 확인 필요.
- 확인된 관계 변화와 완료된 상호작용의 연결. 시간적으로 가까운 변화만으로 원인을 단정하지 않음.
- 플레이어가 직접 반응하거나 지정한 순간. 플레이어 지시는 AI의 자발적 선택과 구분.
- 알려진 취향/약속과 관련된 완료 결과 또는 명확한 미결 상태.
- 반복되는 낮은 강도의 일상. 같은 실패 재시도를 반복된 배려/갈등으로 세지 않음.

최종 선택은 후보 중 중요도, 새로움, 현재 관계/미결 항목과의 관련성, 최근 중복,
내용 다양성을 함께 본다. 관계 수치 +1이나 포옹 1회가 무조건 영구 기억은 아니다.
상위 사건이 없다고 매 시간/매 장면 기억을 억지로 하나 생성하지 않는다.

강한 부정 사건만 골라 관계가 늘 불행하게 보이지 않도록 평온한 공동 활동,
작은 배려, 중립적인 첫 경험도 평가 사례에 포함한다. 반대로 균형을 맞춘다고
일어나지 않은 긍정 사건을 보충하지 않는다.

## 장면 묶기

같은 시간대라는 이유만으로 묶지 않는다. 같은 장면 범위, 참여자, 확인된
상호작용/목표 연결을 기준으로 원인 관계가 있는 하위 행동만 묶는다.

예시(합성 시나리오):

- 원본: B의 낮은 에너지 관찰 → A가 B에게 음식 제공 완료 → B의 수락/식사 확인.
- 사실 요약: **A가 피곤한 B에게 음식을 건넸고 B가 먹었다.**
- 해석 후보: **B는 배려받았다고 느꼈을 수 있다.**
- 금지: 상호작용만 보고 **A가 B를 걱정해서 요리했다**, **둘이 화해했다**라고 확정.

요리만 했고 전달이 확인되지 않았다면 '누군가를 위해 요리했다'로 묶지 않는다.
돌봄 중 C가 전화를 받는 등 독립 사건은 따로 처리하고 압축 과정에서 삼키지 않는다.

장면은 활동 종료, 참여자/장소 변경, 충분한 비활동 등으로 닫되, 끝나기 전 위험
상태는 현재 맥락에 바로 반영한다. 기억 요약을 기다리느라 생존 제어를 지연하지 않는다.
중단된 장면은 완료된 장면으로 바꾸지 않는다.

## 토큰과 비용

- 입력마다 전체 원본을 보내지 않는다. 현재 snapshot + 짧은 최근 맥락 + 관련 장면
  최대 3~6개라는 **항목 상한**에 더해 전체 입력 토큰/바이트 예산도 적용한다.
- 장면 선별/중복 제거는 로컬. 요약을 해야만 대화할 수 있는 구조로 만들지 않는다.
- 장면이 닫힐 때 후보가 있고 예산이 허용하는 경우에만 메인 모델 요약. 초과 시
  짧은 구조화 사실로 유지하며 자동 호출 재시도/무한 대기열을 만들지 않는다.
- 요약문을 매번 다시 요약하지 않는다. 필요한 원본 근거에서 버전이 있는 해석을 만든다.
- 저장된 기록 수와 매 요청 컨텍스트 길이는 별개다. 하루가 길어졌다고 매 요청이
  자동으로 길어지는 구조를 허용하지 않는다. 이 문서는 절약률 실측을 주장하지 않는다.

## 구현 전 수용 사례

1. 100번 반복된 식사 단계가 장기 사건 100개 또는 모델 호출 100회를 만들지 않음.
2. 식사 중 화재가 나면 일반 식사 묶음에 사라지지 않고 우선 맥락이 됨.
3. 취소된 포옹은 '포옹했다'로 남지 않음. 관찰된 거절은 별도 사실로 남길 수 있음.
4. A→B와 B→A를 바꾸지 않고, 플레이어 지시/생존 제어/AI 자발성을 분리함.
5. 모델의 '걱정했어'는 발언이지 과거 의도에 대한 검증된 사실이 아님.
6. 동일 원본 재전송/큐 실패 재시도는 반복 습관 통계에 중복 가산되지 않음.
7. 3배속, 일시정지, 여행, 세이브 시간 역행에서 시간/범위가 섞이지 않음.
8. 평온한 일상만 있는 세션도 유지 가능하며 억지 갈등/이정표를 생성하지 않음.
9. 사용자의 중요 표시가 가상의 내용을 게임 관찰 사실로 승격시키지 않음.
10. 토큰/보관 상한에 도달해도 미결 약속과 현재 위험 상태를 무작정 오래된 순서로 버리지 않음.

# alpha.9 · 콘솔 없는 진입점 프로토타입

## 상태

2026-09-14: 소스 구현 / 무료 자동 테스트 / 게임 Python 3.7 빌드 완료.
**설치 및 인게임 검증은 보류. 현재 설치본은 alpha.8이다.**
사용자가 공부하기 위해 화면·포커스 사용 중지를 요청했다. 그 뒤 CUA 조작,
게임 종료/재실행, Mods 교체, 가족 선택, 저장, 유료 API 호출을 하지 않았다.
앞서 게임 앱을 여는 시도는 타임아웃으로 끝났으므로 실행 완료라고 기록하지 않는다.

## 실제 추가된 구현

- `control_ui.py`: 담벼락의 PlumbMate 열기 → 대화 열기 / 역할 선택 / 닫기.
- 플레이어 심 → AI 심의 두 단계 선택을 끝내면 입력창으로 이어짐. 자동 전송 없음.
- 네이티브 버튼 콜백은 콘솔 연결 ID가 없으므로 실제 `ClientManager.get_first_client()` 경로 사용.
- 전송 성공 안내는 추가 담벼락 알림을 만들지 않는다. 해당 역할/씬에 묶인 최근
  접수 문구 하나를 메뉴에 표시하고, 대기 상태는 기존 상태 창에서 확인한다.
  이것은 로컬 요청 생성 확인이지, 원격 처리 완료나 과금 취소 확인이 아니다.
- AI 답변, 초상화, 실패 안내, 중복/늦은 답변 차단은 기존 경로 유지.

## 구조와 안전장치

- UI 담당 모듈을 분리하고 commands는 연결만 담당한다.
- 게임 스레드의 메모리 전용 lifecycle 확인은 실제 시간 5초 간격. 파일 읽기,
  stat, 워커 생성, API 호출 없음. 동반 앱이 없을 때도 동작한다.
- 하나의 현재 로트/가족 launcher만 보유하며 전환/stop/reload 때 자기 창만 해제.
  이전 창은 동일 가족에서 stop/start 후에도 epoch로 무효화한다.
- show 오류는 연속 스코프당 3회까지만 시도. UI 실패는 transport 연속 실패
  카운터와 분리되어 정상 응답 수신을 중단시키지 않는다.
- 게임의 전역 notification 클래스나 다른 모드 창을 덮어쓰지 않는다.
  자기 subclass의 `respond=False` 경로로 서버 등록을 유지한다.
- 메뉴의 닫기/취소/알 수 없는 응답은 역할 변경이나 전송으로 해석하지 않는다.

## 확인한 증거

- 전체 unittest **371개 통과**, 15.634초. 화면 접근·유료 호출 없는 임시 localhost 테스트.
  기본 sandbox에서는 localhost bind가 차단되어 그 실패를 분리한 뒤 권한 범위 내 재실행했다.
- `game_mod/verify_control_ui_contract.py`: 해시 고정 게임 bytecode에서 응답 ID,
  추가 버튼, 리스너 연결 확인. 실제 `UiDialogService.dialog_respond` 메서드를
  소유한 fake 객체에만 실행해 반복 활성화/닫기/예외 cleanup 확인.
- 실제 UI 클래스 import·표시를 한 검사가 아니다. 이 구분을 유지한다.
- `dist/PlumbMate-alpha9.ts4script`: 10개 root pyc, 게임 magic `420d0d0a`.
- SHA-256: `a01e4b6f09c82c397111e4a7801aa1d1bbff87cb9fbf9d38fec558652b20a328`.
- 설치 폴더에는 복사하지 않았다. 원격 push/공개 배포도 하지 않았다.

## 화면을 사용할 수 있을 때의 필수 수용 검사

1. 네이티브 subclass TunableFactory가 실제 런타임에서 생성되는지.
2. QA 가족 입장 후 강제 팝업 없이 launcher 버튼이 보이는지.
3. 같은 버튼을 두 번 이상 눌러 다시 메뉴를 열 수 있는지. 서버 등록 유지가
   클라이언트 버튼 재사용까지 보장한다고 가정하지 말 것.
4. 콘솔 없이 역할 두 명 선택 → 한글 입력 → 실제 이름/초상화의 mock 답변.
5. 성공 안내는 별도 담벼락을 채우지 않고 재진입 메뉴/상태 창에 보이는지.
6. 닫기·취소·중복 클릭·로트 전환·stop/reload·동반 앱 꺼짐에서 재전송 없는지.
7. 알림 삭제/모두 지우기 동작 및 사용자 복구 경로 확인.

## 아직 완성되지 않은 사용감

이것은 **휴대폰의 문자 보내기 메뉴가 아니다**. 기존 동일 가족/로트 제한도 유지한다.
알림을 사용자가 삭제했을 때 자동으로 다시 띄우지 않으므로 영구적인 클릭 진입점으로
완성됐다고 할 수 없다. 복구는 현재 `plumbmate.ui` 또는 로트 재진입이다.
실제 버튼 재사용 검증 뒤 휴대폰/심 메뉴의 별도 tuning/injection 작업을 결정한다.

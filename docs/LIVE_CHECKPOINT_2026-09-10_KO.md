## alpha.5 실게임 확인 결과

- 사용자가 콘솔을 열어 준 뒤 `plumbmate.status`로 alpha.5 / tick hook installed / autostart bound 확인.
- `plumbmate.setup`의 2단계 선택창에서 플레이어 **썸머 할리데이**, AI **트래비스 스코트**를 각각 선택. 역할 결과 알림 확인.
- 현재 선택된 심은 트래비스지만 발신 역할은 썸머로 유지됨.
- `plumbmate.chat` 기본 창의 받는 사람 표시, 빈 입력 시 전송 비활성화 확인.
- 한/영 전환 후 물리 키 입력으로 **안녕**을 조합하고, **안녕, 오늘 같이 산책할까?** 문장을 붙여넣어 전송.

- 그 뒤 `plumbmate.read` 실행: **이미 표시한 답변이에요** 출력. 새 답변 알림이 생기지 않음.
- 다시 빈 입력창을 열고 취소: 새 요청/처리 상태 파일 없음.

사용자는 한글 입력 소스일 때 콘솔 단축키가 안 먹는다고 알려 줬다.
CUA에서는 짧은 단축키가 여전히 안정적이지 않으므로 한/영 전환만으로
모든 키 자동화 문제가 해결됐다고 단정하지 않는다. 붙여넣기는 도구가 timeout을
반환해도 실제 필드에는 입력됐으므로 항상 화면 재확인 후 다음 행동을 했다.

지도 부지는 CUA의 일반 click으로 선택되지 않았지만 같은 위치의 drag로
선택되었다. UI 버튼 클릭은 작동한다. 이는 관찰 결과이며 엔진 입력 타이밍의
원인이 확정됐다는 뜻이 아니다.

## alpha.6 변경과 자동 검사

- 입력창의 옛 `plumbmate.read` 필수 안내를 자동 알림 안내로 수정.
- 전송 접수 알림을 줄이고, 기술적 상태를 캐릭터 대사와 분리.
- 180초 대기 만료 시 같은 요청/역할/장면에만 시스템 안내 1회.
  새 가족·역할·요청, 이미 표시한 응답에는 안내를 남기지 않음.
  만료 안내도 게임 스레드의 UI만 사용하며 파일 읽기/모델 호출/자동 재전송 없음.
  UI/콘솔 예외나 callback 재진입이 알림 반복을 만들지 않도록 종료 후 호출.
- mock은 무엇을 말해도 “좋아”라고 동의하던 문구와 고정 데이트 제안을 제거.
  수신 확인임을 명시하고 기억 패치도 생성하지 않음. 실제 모델 품질 개선을 가장하지 않음.
- 전체 **336개 테스트 통과**(15.000초), 스키마 export 및 diff 검사 통과.
- 설치 게임의 Python 3.7로 9개 production 모듈 빌드 성공.

```text
dist/PlumbMate-alpha6.ts4script
SHA-256: 7eaa3113098d9c7514e46022c31c8e94888d55ea8fc35e9514f3b7489c848e62
```

게임 UI의 **저장 없이 종료** 후 해당 프로세스가 사라진 것을 확인했다.
강제 종료 없이 `PlumbMate.ts4script` 한 파일만 백업 후 교체했고 설치본 hash가
위 alpha.6 빌드와 일치함을 확인했다. 백업은 git 제외 경로
`dist/install-backups/2026-09-10-alpha6/PlumbMate.ts4script`에 있다.
기존 mock 동반 앱을 SIGINT로 종료한 뒤 새 mock 프로세스 한 개를 실행했다.
`doctor --connect` 성공, `api_calls: 0`.

사용자가 감정 노트/풍선 UI의 구현 부담을 먼저 검토해 달라고 요청해 게임은
재실행하지 않았다. **alpha.6의 변경 문구/만료 알림은 자동 검사 완료,
실제 게임 화면 재검증 전**이다. 감정/풍선 기능은 설치본에 추가하지 않았다.

- 수동 `read` 실행 전에 알림 담벼락에서 **트래비스의 얼굴, 이름, 같은 메시지가
  포함된 mock 수신 확인**을 확인했다. 게임은 일시정지 상태였다.
- 이후 `plumbmate.read`는 **이미 표시한 답변이에요**로 차단. 초상화 알림 중복 없음.
- 새 역할/접수 안내와 캐릭터 답변의 구분 유지. mock은 실제 AI 발화가 아닌 연결
  검사임을 본문에 명시한다. 유료 API 호출, 실제 행동 실행, 저장 명령 없음.

alpha.6의 변경된 입력/접수 문구는 위 alpha.7 검사에서 확인했다.
180초 만료 알림과 모든 UI 예외 상황은 자동 검사만 완료했으며 실게임 확인은 별도다.
이는 이번 한 가족/한 게임 빌드의 성공이며 Windows, 다른 종족/나이, CAS 변경,
로트 전환까지 검증했다는 뜻은 아니다.

1. 콘솔 없이 역할 설정/대화를 여는 진입점. 실제 EA 메뉴 구조를 확인하고 작게 연결할 것.
2. 사용자가 선택하는 인격·말투와 **실제 모델** RP 품질 평가. mock 테스트가 이를 증명하지 않음.
3. 동의한 비용 정책을 통한 실제 provider 검증. 이번에는 유료 API를 사용하지 않음.
4. 저장 계보에 연결된 기억/프로필 복원. 현재 장기 기억은 안전상 비활성화이며, 모델만 바꿔도 기억이 생기는 구조가 아님.
5. 긴 한글/이모지 입력, 로트 전환 및 연결 중단 시 실제 UI 검증 확대.

일반화 원칙: QA의 심 이름은 테스트 데이터일 뿐 코드에는 고정하지 않는다.
main 머지/공개 배포 없음. 개인 세이브나 채팅 원문 파일은 업로드하지 않는다.

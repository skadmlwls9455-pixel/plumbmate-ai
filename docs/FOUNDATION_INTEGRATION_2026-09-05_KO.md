# Foundation 통합 작업 계획

기준: `96a8b7e` (Lumen), `d45a4d0` (Fable PR #1). 배포나 main 머지가 아닌 개발 브랜치 작업이다.

## 변경 전에 정한 책임과 정책

1. 게임 명령 어댑터는 EA 상태 조회와 콘솔 입출력을 담당한다. 네트워크 펌프는 기존 `tick_driver`/`bridge_client`에 남긴다. 틱 경로의 파일 I/O 금지는 유지한다.
2. 요청·응답의 구조/길이/허용 필드는 **동반 앱의 패키지된 JSON Schema**가 정의한다. 런타임 검증과 모델 출력 계약이 같은 정의를 사용한다. 파일 읽기·격리는 `protocol`/`engine` 책임이며 검증 모듈은 게임 API를 import하지 않는다.
3. 연결 설정은 영구 설정이다. 파일 존재를 생존 신호로 쓰지 않는다. 동일 주소 재연결은 자동, 포트·토큰 변경은 명시적 reload다.
4. 서버 start/stop은 하나의 제어 스레드에서 호출한다. 종료 마감 내 기존 워커가 남으면 참조를 유지하고 재시작을 거절한다. 세대가 다른 워커를 새 서버에 섞지 않는다.
5. 잘못된 요청은 provider에 보내지 않는다. 불확실한 API 실패는 자동 재시도하지 않는다. 검증되지 않은 세이브 범위의 모델 기억을 사실로 복원하지 않는다.

## 이번 구현 범위

- 다단어 채팅, 활성 심 없음, 유니코드 경로/호스트 입력 회귀 수정.
- Fable의 서버 재시작, accept 일시 오류, 종료 경쟁, 워커 생성 실패, 핸드셰이크 총시간 제한을 검토해 선택 통합.
- 요청/응답 계약의 단일 원본, 추가 필드 차단, 최종 응답 재검증, 손상 요청 격리.
- 합성 게임 스텁 → 요청 파일 → mock companion → 응답 읽기의 양성 통합 검사.
- 전체 회귀 검사와 실제 설치본 Python 3.7 바이트코드 빌드. 빌드는 인게임 검증이 아니다.

## 다음 단계 (이번에 구현됐다고 주장하지 않을 것)

- 인게임 다단어 채팅/stop-start/다른 래퍼 공존 스모크.
- ACK 기한·keepalive·미전송 outbox 이관 계약과 테스트.
- 파일 교환은 이번 작업 중 `turn_bridge`로 분리 완료. EA 스냅샷/연결 설정 경계의 추가 정리는 후속 후보.
- 세이브 영수증 → 분기 격리 → 관찰 사실 저장을 하나의 수직 기능으로 완성.
- 실제 사용량/비용 한도 후 모델 라우팅과 IC 실행기를 단계적으로 연결.

## 반복 개선 규칙

결함 재현 → 실패하는 검사 → 책임 경계 확인 → 최소 수정 → 회귀/계약/빌드 확인 → 실제와 설계 문서 갱신. 테스트 개수 자체를 품질 목표로 삼지 않는다. 실제 게임과 스텁 증거를 구분하고, 성능 최적화는 측정값 없이 수치 효과를 주장하지 않는다.

## 9월 6일: 사용감·장기 토큰 피드백에 따른 범위 보완

- `budget`는 검증된 입력의 선택·크기 제한을 담당한다. 기본 context JSON은 UTF-8 12,000바이트 이하. 현재 발화와 actor는 보존하고, 부가 household와 오래된 recent_events를 먼저 덜어낸다. 전체 히스토리를 매 턴 붙이지 않는다. 이는 정확한 토큰/달러 상한이 아니다.
- 유료 호출 횟수 제한은 `engine`의 세션 정책 한곳에서 관리한다. CLI마다 다른 카운터를 만들지 않는다. 실패한 시도도 차감하고, 한도 소진 뒤에는 새로운 요청을 조용히 대기시키지 않고 거절 상태를 남긴다.
- 요청 상태 파일은 진단용 메타데이터만 가진다: request_id, phase, reason_code. 대화 원문·키는 넣지 않는다. 상태 기록은 best-effort이며 세이브 영수증이나 분산 트랜잭션 원장으로 취급하지 않는다.
- `plumbmate.read`는 실패/한도 소진을 구별해 표시한다. 다만 동반 앱 연결 상태와 LLM 처리 상태는 서로 다르다. 자동 응답 표시/심 지정/메뉴 UI는 후속 사용성 단계다.
- 프로세스 재시작으로 횟수 제한이 초기화된다. 일일 금액 한도, 실제 usage 회계, 충돌/크래시를 포함한 영속 idempotency는 별도 필요하다. 이번 안전장치를 그 기능으로 과장하지 않는다.

## 선택 통합 결과

Fable PR #1의 채팅 시그니처, 유니코드 입력, 서버 수명주기/인증 deadline 수정 방향을 채택했다. 서버 회귀 검사 3개와 CI 구성은 원 PR을 바탕으로 가져와 확장했다. 이전 워커 종료 확인, 총 stop deadline, 스레드 생성자 실패, 지연 accept 경쟁 검사도 추가했다. 브랜치 전체를 병합한 것은 아니며 endpoint 생존 파일, 유료 호출 재시도, 모델 patch 기반 기억 복원은 채택하지 않았다.

계약 모듈과 모델 출력 스키마는 [OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 필수 필드/추가 필드 금지 제약을 확인하고 구성했다. 실제 API는 호출하지 않았으며 모델별 호환성은 별도 검증 사항이다. 검증기는 [python-jsonschema 공식 문서](https://python-jsonschema.readthedocs.io/en/stable/validate/)의 Draft 2020-12 구현을 사용한다.

- **미실시**: 이번 수정본 인게임 설치·가족 플레이·실제 모델 API 호출. main 병합·릴리스·Saves/Tray/다른 모드 변경 없음. CI 정의는 추가했지만 원격 실행 결과는 별도 확인한다.

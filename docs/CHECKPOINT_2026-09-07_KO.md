# 2026-09-07 중단·재개 체크포인트

## 먼저 알아둘 것

사용자가 사용량 초기화 전에는 중단해도 안전한 작은 작업만 요청했다. 이번 체크포인트에서 새 역할 UI나 알림 자동 전달을 성급히 구현하지 않는다. 심 위 로딩창은 사용자가 명시적으로 제외했다. 게임 저장, 추가 심 생성, 유료 API 시험과 공개 배포는 하지 않는다.

이전 원격 기준: `lumen/bridge-reliability`의 `dd2977d`. 아래 변경은 이번 로컬 작업이며, 별도로 push/CI를 확인하기 전 원격에 반영됐다고 말하지 않는다.

## 코드로 구현한 변경

금액 한도는 **사용자가 검토한 가격표에 따른 PlumbMate 로컬 호출 제한**이다. 공급자 계정 전체의 청구 상한, 실제 청구서, 세금·환율·다른 앱 사용량을 보장하지 않는다. 한 가격 설정과 그 옆 원장을 공유하는 실행들에 적용된다. 다른 설정/원장을 만들면 별도 범위가 되므로 일상 운영에서 원장을 복제하거나 삭제하지 않는다.

입력 계산 API에도 해당 문맥을 전송한다. 생성 호출은 승인된 설정·예약·입력 상한 검증 뒤에만 보낸다. 사전 계산 실패, usage 누락, 다른 모델/서비스 등급, 전송 결과 불명은 예약을 유지한다. 초기 모델 출력 상한은 설정 가능하며, 작은 상한에서 불완전한 응답이 나와도 요금 기록 후 중단하고 자동 재시도하지 않는다.

`budget reconcile`는 환불 기능이 아니다. 모든 동반 앱과 진행 중 호출을 중지하고 공급자 측 결과를 확인한 운영자가 `--request-id`, `--confirmed-usd`, `--confirm-no-active-calls`로 원장을 보정한다. 과거 상태는 adjustments에 남으며 원래 request ID는 재사용할 수 없다. 미확정 요청을 자동으로 무료 처리하지 않는다.

## 검증 증거와 한계

- 전체 회귀: **261개 통과, 11.985초**. 중복 ID·기한 입력 검증·비용 정산/마이그레이션 검사 포함. `git diff --check`와 schema export 검사도 통과했다. 이는 로컬 결과이며 이 변경의 원격 CI 결과가 아니다.
- 합성 500턴 benchmark: 문맥 JSON 평균 785→549 UTF-8 bytes, 중앙값 약 0.164ms, p95 약 0.172ms. 한 번의 로컬 측정이며 토큰 수·전체 프롬프트·비용 30% 절감을 뜻하지 않는다.
- 실제 게임 `1.127.41.1230`에서 `0.1.1-alpha.2` 로드 확인.
- `plumbmate.chat 오늘 같이 산책하고 사진 찍을까?` → 로컬 mock → `plumbmate.read` 한글 왕복 확인. 첫 화면 도구 typeText는 한글이 누락됐고 붙여넣기 경로로 전체 문장을 확인했다. 사용자 직접 IME 입력 및 새 입력 UI 검사는 별도로 필요하다.
- 실게임 연결: READY, 한 번의 연결/핸드셰이크, heartbeat 7개 모두 ACK, failures/lost/errors 0인 스냅샷 확인. 장시간·모든 모드 조합 호환성을 뜻하지 않는다.
- `doctor --connect`: 모든 점검 통과, 외부 API 호출 0.
- 유료 API·실제 청구·모델의 RP 품질은 시험하지 않았다. 사용자에게 모델/금액 승인을 받기 전 계속 mock만 사용한다.
- 설치한 시험 빌드 SHA-256: `1a3030882a570aa46fe41f335fa7257ed0c581a176742d382d4a12233d587c29`. 설치 후 추가된 중복 이벤트 ID/기한 인자 방어는 아직 이 빌드에 없다. 최신 소스로 재빌드·게임 종료 후 설치·재검증해야 한다.
- 이전 두 모드 파일은 `dist/install-backups/2026-09-07-alpha2/`에 보존했다. 다른 CC/모드/Tray를 수정하지 않았고 저장 명령을 실행하지 않았다. 종료 후 세이브 파일 메타데이터 불변 검사는 아직 남았다.

## 실제 사용감에서 발견한 핵심 결함

현재 `actor`는 선택된 심이다. AI 파트너가 명시적으로 지정된 것이 아니며, mock이 선택 심 이름으로 답해 역할이 있는 것처럼 보일 수 있다. 현재 가족에는 심 한 명뿐이다. 이것은 연결 테스트 성공과 제품 사용 가능을 혼동한 문제다.

검토의 기준을 코드·통신 통과에서 **새 사용자의 첫 대화 전체 경로**로 확장한다. 역할 선택·대화 UI·준비 상태가 없는 상태를 완성된 AI 파트너 플레이로 소개하지 않는다.

## 다음 작업 순서 — 한 묶음씩

1. 역할 계약과 픽스처: 플레이어/AI 심 분리, 동일 심 금지, 다른 세이브/가족 검증, 미지정 시 안내. 첫 제품 범위는 같은 가족의 두 심을 제안했으며 실제 선택 UI 세부안은 합의 전이다.
2. 비용 있는 호출 이전의 준비 검사: 역할·연결·공급자·동의·금액을 분리. 지금 미지정 상태에서도 가능한 개발용 mock과 실제 파트너 대화를 구분한다.
3. 입력창 UI: 수신자를 항상 표시, 전송 완료·응답 준비·지연·실패를 메시지 근처에 작게 표시. 선택 심을 바꿔도 역할이 자동 교체되지 않게 한다.
4. 알림 담벼락: 게임 설치본의 실제 notification API/서명부터 확인. 대사와 기술 오류는 서로 다른 시스템 표현으로, 비공개 생각은 표시하지 않는다.
5. 자동 전달: 응답 ID + 요청 당시 역할 + 세션/씬 유효성 검사, 한 번만 표시, 늦은 답변 폐기. 게임 틱의 파일 폴링을 재도입하지 않고 bounded 소켓 경로를 설계·검증한다.
6. 두 심 합성 테스트 및 사용자 허용된 실게임 시나리오. 현재 한 명뿐인 가족에 임의로 심을 추가하지 않는다.

### UI 수용 기준

- 심 위 로딩창/감정 온도계를 기본으로 만들지 않는다.
- 준비 상태는 입력 패널 근처의 작고 명확한 텍스트/표식으로 먼저 검토한다. 정확한 문구·레이아웃은 아직 확정하지 않는다.
- “응답 준비 중”은 시스템 상태다. 네트워크 오류를 “캐릭터가 삐졌다/망설인다”는 서사로 숨기지 않는다.
- 시스템 알림은 낮은 방해 수준으로 원인과 다음 행동을 제공한다. 정상 대사와 디자인 톤은 맞추되 화자와 성격을 혼동시키지 않는다.
- 전송 직후 피드백, 중복 전송 방지, 중복 표시 방지, 예전 역할/세이브의 늦은 답변 차단을 자동 테스트한다.
- 초보 사용자가 request ID, JSON, 콘솔 `read` 명령을 몰라도 첫 대화에 도달해야 한다.

## 재개 시 주의

- 현재 게임/동반 앱 상태를 새로 확인한다. 이전 테스트 앱은 mock, 8회 제한으로 시작했지만 실행 지속 여부를 추정하지 않는다.
- 이전 턴에 받은 실제 Mods 쓰기 권한은 다시 필요할 수 있다.
- 로컬 변경·실제 설치 빌드·원격 커밋을 따로 확인한다. 새 사용자 메시지가 오면 이 체크포인트보다 우선한다.
- 저장/가족 생성/유료 API를 새로 허가받았다고 가정하지 않는다.
